# Aurora 聊天 API v1 设计稿

状态：本机后端已实现，登录和前端待接入。

## 1. 从学生的操作出发

学生点击「新建对话」创建会话，问“反相比例电路的输出怎么算？”，然后在同一会话追问“那把 R1 换成 20k 呢？”。刷新页面、退出后重新登录同一账号或服务重启后，只要会话未删除，用户仍可用原 ID 读取已保存的历史并继续追问。

这条流程涉及两个资源。**会话**持有多轮历史，**消息**属于会话，包含学生原话和助教回答。一次发送请求同步完成一轮问答。课件检索、分类和工具计算由 `pipeline.run()` 编排。先在单进程本地原型中实现持久化聊天，再接入登录和会话归属校验，完成后方可开放给多个学生。自助注册可后续按需实现。

## 2. HTTP 接口

业务路由统一使用 `/api/v1`。请求和响应使用 JSON，`204` 响应无正文。

| 方法与路径 | 成功响应 | 用途 |
| --- | --- | --- |
| `POST /api/v1/sessions` | `201`，`{"session_id":"<uuid>"}` | 创建空会话，由服务端生成 ID |
| `GET /api/v1/sessions` | `200`，`{"sessions":[{"session_id":"<uuid>"}]}` | 列出当前用户的会话，重新登录后可据此找回旧会话 |
| `POST /api/v1/sessions/{session_id}/messages` | `200`，本轮助教回答 | 提问或追问 |
| `GET /api/v1/sessions/{session_id}/messages` | `200`，`{"messages":[...]}` | 按写入顺序读取文字历史，新会话返回空数组 |
| `DELETE /api/v1/sessions/{session_id}` | `204` | 删除会话和历史 |
| `GET /health` | `200`，`{"status":"ok"}` | 检查服务进程能否响应 |
| `GET /ready` | `200`，`{"status":"ready"}` | 检查本地索引和服务配置的初始化状态 |

发送消息的请求体为 `{"content":"那把 R1 换成 20k 呢？"}`。`content` 必须是字符串且去除首尾空白后非空。校验通过后，原始文本进入 Pipeline 和会话历史。

成功响应示例。这里走运放计算分支，检索来源为空。

```json
{
  "role": "assistant",
  "content": "R1 改为 20kΩ 后，反相增益按 -Rf/R1 重新计算。",
  "circuit_type": "opamp",
  "retrieval_sources": []
}
```

`circuit_type` 使用现有五类标签 `opamp`、`feedback`、`power`、`concept`、`fallback`。`retrieval_sources` 是从 `hits` 转换的对象数组，每项只含 `source` 和可空的 `heading`。它表示检索命中来源，不能证明回答引用了该片段。内部 `trace`、改写文本、分类理由和相似度不进入公开响应。

历史中的每条消息只有 `role` 和 `content`，例如 `{"role":"user","content":"那把 R1 换成 20k 呢？"}`。现有 `Session` 只保存纯文本，因此刷新后的历史可以恢复问答文字，本轮返回的分类和检索来源只在发送响应中提供。

## 3. 状态与写入

- 持久存储保存会话 ID、`owner_id` 和有序的文字消息。每次提问时从已保存的历史构造独立的 `Session`，交给 `pipeline.run(content, store, session=session)`。Pipeline 成功后，API 将本轮问答作为一个事务保存，提交成功后才返回 `200`。能力边界提示与空索引提示同样成对保存。
- 本机使用 FastAPI 和单 worker Uvicorn。应用内互斥锁串行处理会话操作，覆盖读历史、生成和保存。先处理发送时，问答保存后再处理删除。先处理删除时，随后的发送返回 `404`。
- 显式删除结束聊天会话的生命周期。退出登录只结束访问资格，服务重启后从持久存储读回原会话和历史。
- 启动时加载一个进程内只读 `VectorStore`。索引无法加载时，`/ready` 和发送接口返回 `503`。成功加载但无内容的索引保留现有降级回答。`/ready` 不调用模型探测上游。

## 4. 身份与访问权限

- 服务端在创建会话时根据当前身份写入 `owner_id`。本地单人开发模式使用服务端配置的固定开发身份，并仅监听本机。共享环境使用真实登录身份，关闭开发身份。
- 列表只返回当前用户的会话。读取历史、发送消息和删除会话都按当前身份校验归属。会话 ID 只用于定位记录，所有者由服务端确定。

## 5. 失败响应

错误正文统一为 `{"error":{"code":"session_not_found","message":"会话不存在或已失效"}}`。前端依据 `code` 处理，公开消息不包含堆栈、模型凭据或本机路径。

| 状态码 | `error.code` | 触发条件 |
| --- | --- | --- |
| `422` | `invalid_request` | 请求体缺字段、类型错误或内容为空白 |
| `401` | `authentication_required` | 共享环境下缺少有效登录态 |
| `403` | `local_access_only` | 本机服务收到非回环 Host 或跨源请求 |
| `404` | `session_not_found` | 会话不存在、已删除或属于其他用户 |
| `503` | `service_not_ready` | 索引或必要配置未就绪 |
| `502` | `upstream_error` | 可识别的上游请求或模型响应失败 |
| `500` | `internal_error` | 未预期的服务端错误 |

请求校验失败、服务未就绪、生成失败或保存事务失败时，已保存的历史保持原样。HTTP 响应可能在事务提交后丢失，前端遇到超时应先读取历史，再由用户决定是否重发。首版每次成功提交都会新增一轮，暂不提供重试去重。

## 6. 实施和验收

先用本地开发身份打通创建、列表、提问、历史和删除，再验证重启后的会话恢复。开放多人试用前接入登录、退出和归属校验。具体登录路由和凭据机制留待身份方案定稿。

定稿后，按 [测试计划](testing/TEST_PLAN.md) 登记稳定 Test ID，再实现离线接口测试。验收至少覆盖以下场景。

- 同一会话连续两轮，第二轮看到第一轮上下文，历史按 `user / assistant` 成对追加。
- 服务重启后，原 ID 可以读历史并继续追问。接入登录后，退出再登录同一账号能从列表找回会话，其他账号不能读、写或删。
- 保存事务失败时不留下半轮消息。
- 不同会话历史隔离。并发发送保持问答成对，发送与删除竞争时已删除的会话不会恢复。
- 非法请求、未知会话、索引未就绪和上游失败返回约定的状态码，失败轮次不写入历史。
- 空索引正常返回可见提示并写回历史。检索结果只公开来源字段，响应不包含内部工具跟踪。
